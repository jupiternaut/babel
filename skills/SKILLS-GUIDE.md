# 开发包内的设计技能

这三份技能用于 Nimbalyst GUI 与独立 TUI 的局部设计与检查，按 [TUI/CLI 与 Hooks 契约](../NIMBALYST-TUI-HOOKS-SPEC.md) 和 [视觉合同](../design/visual-contract.md) 适配。它们是从本机保存的 Interfaces 上游源码快照携带的参考文件，不是已经接入 Nimbalyst 的插件，也不会自动安装或执行。项目功能、Tracker 映射和用户已经确认的视觉方向决定实现；技能只补充专项判断。

## 按工作选择，不同时加载整套

| 当前工作 | 读取入口 | 作用 |
| --- | --- | --- |
| GUI 栏位与卡片、TUI 列表/详情、尺寸适配 | [better-layout](vendor/better-layout/SKILL.md) | GUI 复用组件与 tokens；TUI 按字符网格保持阅读顺序与渐进展开 |
| 卡片/列表、菜单、弹窗、终端输入与拖拽替代 | [better-accessibility](vendor/better-accessibility/SKILL.md) | 焦点、键盘、鼠标、状态文字；终端能力需实测，不把 DOM/ARIA 写法机械移植 |
| 三端动作、状态标签、失败提示与空状态 | [better-writing](vendor/better-writing/SKILL.md) | 让文字对应共同命令的实际动作、拒绝原因和结果 |

需要相应专项时，由开发 Agent 显式读取入口，再按需读取入口链接的参考文件。不把 `skills/vendor/` 全量粘贴进提示词，不修改用户全局技能目录。携带技能不自动注册开发工具 hook；Babel 应用级 Hooks 则按补充契约实施和测试，两者独立。若某个 Agent 工具支持自动技能发现，接入应是后续明确的配置工作；本包目前只提供可移植的参考文件。

## 本项目适配规则

1. **保留已有产品系统。** GUI 使用 Nimbalyst 既有组件、字体、图标库、主题与 tokens；第二版图仅是方向参考，以当前规格和视觉合同为准。TUI 映射相同业务语义，使用终端字符网格、颜色与焦点机制。CSS px、圆角、触屏热区及动画数值不直接强加 TUI；技能里的通用默认值不能重建产品架构或取代项目约束。
2. **主要工作区保持简洁。** GUI 左侧容纳工作区、设备、项目、视图和集成入口；中央显示生命周期列及必要卡片信息，右侧按需展开详情。TUI 按可用列数选择列表/看板和详情切换，保留可发现的导航、操作菜单与帮助，不强制三栏。两端都不加入装饰图表、营销首页或无必要动效。
3. **同记录、同 ID、同权威源。** 原生 Trackers 与新看板是同一条记录的两个视图，不为看板复制任务。GUI 内共享 provider 实例，跨进程 TUI/CLI 共享服务、协议、项目作用域、revision 和事件游标。类型、Saved Views、Ready、正文和会话关联按 [Trackers 映射](../NIMBALYST-TRACKER-MAPPING.md) 处理，三端路径登记在 [能力矩阵](../CAPABILITY-MATRIX.md)；技能不能改变领域契约或绕过守卫。
4. **状态文案忠实。** Releases 是发布记录，不是归档；`approved` 不等于完成；创建 Session 或草稿不等于 Agent 已开始执行。启动、失败、完成和归档标签必须对应规格规定的事件与实际可验证状态。尚未取得有效观测显示“未知”；超过 freshness 阈值显示“快照过期”；最近连接探测失败按实际层级显示“SSH 不可达”或“节点不可用”，并展示观测时间。未知或过期不能推断设备离线、Agent 已停止；SSH 可达也不等于 Worker 或 Agent 可用。
5. **M0 交付三端无 Key 原型及 Hooks。** GUI、TUI、CLI 连接同一个明确隔离的 demo 服务，fixture 初始化一次并清楚标记演示数据；三端可操作完整模拟闭环，并以合成 Hooks 验证校验、投递和故障恢复。不能调用云端 Agent、读取已有凭据、SSH 连接真实设备或把模拟状态写入实际项目。真实运行接入属于后续阶段。
6. **两端均有完整键盘路径。** 选择、编辑、详情、菜单及业务命令可纯键盘完成；GUI 拖拽提供等价操作。TUI 另实测鼠标选择、滚动和菜单；支持不足时保留键盘路径。弹窗关闭恢复焦点，实时更新不抢输入；低色彩终端同样用文字说明状态与禁用原因。
7. **分别按像素和字符网格验收。** GUI 按规格断点检查窄屏、200% 缩放、中文长标题、空数据与错误状态。TUI 检查 120×40、80×24、160×48 列×行、resize、中文宽字符、输入法/粘贴、光标与换行，缩放或切视图不清空草稿。具体终端和平台支持记录在报告中，不能由浏览器检查推定终端通过。
8. **核对真实实现和业务证据。** GUI 保留五图覆盖并检查实际组件；TUI 交付实际终端截图和 PTY/ConPTY 输入测试，验证重连及退出恢复。AI 生图或 CLI 测试不算 TUI 通过。三端对等和 Hooks 测试同时核对命令结果、关联事件、查询断言；Hook 退出码 0 不代表业务完成，也不能代替 GUI/TUI 操作测试。
9. **如实报告。** `Block` / `Approve` 是技能给出的审查结论，不是新增用户许可流程。未运行的检查写“未验证”；发现问题则按已授权的工作范围修复并复测，不能用技能格式掩盖遗漏。

## 为什么不把所有设计技能都放进来

本机此前保存的 7 套、166 个设计技能是技能库，不是这次项目的必需依赖。对现有 Nimbalyst 做可追溯的局部改造，三份专项指南更容易保持一致。

| 未默认携带 | 原因 |
| --- | --- |
| Impeccable | 本机版本的入口要求运行原生 CLI，首次可下载二进制，带有路径及运行环境依赖；也可能引入另一套设计文档与 hooks |
| better-ui | 包含强制按钮缩放、图标模糊与动画数值，本阶段优先沿用现有 Nimbalyst tokens 与动效 |
| break | 擅长单组件样本检查，但“只看一次”和无现成浏览器则跳过等流程限制不适合作为本项目总验收流程 |
| Taste、Scroll 与营销视觉类集合 | 主要面向创意页面、首屏或滚动展示，容易扩张中央看板；部分依赖外部素材生成服务 |

后续如果确有专项设计问题，增加一份与问题匹配的技能即可，不需要为了“给 Agent 更多上下文”而全量复制。
