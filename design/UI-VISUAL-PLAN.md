# Nimbalyst GUI/TUI 视觉覆盖与验证计划

版本：候选 v3，2026-09-16。对齐 v2.3 业务合同及 UI/UX 主导的 macOS 开发方向；新玻璃母版尚待原生窗口验证，不表示最终界面已批准。

共同约束：[视觉合同](visual-contract.md)、[开发 SPEC](../NIMBALYST-DEVELOPMENT-SPEC.md)、[Trackers 映射](../NIMBALYST-TRACKER-MAPPING.md)、[TUI/CLI 与 Hooks 契约](../NIMBALYST-TUI-HOOKS-SPEC.md)。三端能力逐项登记在 [能力矩阵](../CAPABILITY-MATRIX.md)；现有 [v2 图](babel-dashboard-v2.png) 是 GUI 方向稿。

## 1. 结论与最小范围

需要补关键视图，避免开发 Agent 只凭一张运行画面猜测新建、验收、历史及原生类型入口。GUI 保留五张主图加四类交互／变体验证；TUI 另有实际运行的场景与交互基准。每个状态都画整页既不能证明交互，又会增加不同图之间的冲突。

UI/UX 主导场景与优先级，设计和 Mac 原生运行基线并行推进。按 V01 → V03 → V02 → V04 → V05 形成可操作切片；先精修浅色磨砂主稿，同步检查深色适配，每个切片同时提供交互与业务证据。复用正式组件和隔离 demo 服务；浏览器预览辅助调试，真实 Electron 窗口用于验收。不自动批量生图，也不等待全部后台功能完成才开始视觉工作。

## 2. GUI 的九个覆盖场景

| 编号／优先级 | 场景与固定焦点 | 交付方式 | 关键判定 |
|---|---|---|---|
| V01／P0 | 首页，Trackers 的视图／类型展开，右栏关闭 | 原生可操作母版与截图；构图未定时补候选图 | Ready、类型、显示入口可发现；中央保持四列；无任务被自动启动 |
| V02／P0 | 选中 TODO：说明、依赖、验收和启动摘要 | 独立候选图；新建／校验／保存用交互 fixture | 原生 TrackerItemDetail 数据完整；保存、保存并启动、启动前核验清楚 |
| V03／P0 | 选中“接入任务同步”：当前 run 会话 | 沿用 v2 结构，落实新材质的原生运行母版 | 左栏映射补齐；运行／完成／归档列无新建；消息、工具、补充输入清楚 |
| V04／P0 | 当前执行待人工审查，查看差异和验收证据 | 独立候选图 | 不将退出进程或 approved 当 DONE；接受与要求修改有明确语义 |
| V05／P0 | 归档任务的执行历史；查看旧 run | 独立候选图 | 归档与完成分开；恢复不会执行；不同 run 与人工讨论不混淆 |
| X01／P0 | 同一记录在原 Trackers 与执行视图之间切换 | 可交互 fixture＋实现后的成对截图／录像 | ID、类型、字段、revision 一致；原生 Releases 不能变为归档 |
| X02／P1 | 等待输入、失败、失联、取消待确认、版本冲突、空状态、加载态 | 可注入状态的 fixture；必要时一张组件状态图 | 错误文字和可用动作正确；失联不允许盲目重试；拒绝命令不伪装成功 |
| X03／P0 | 深色、窄窗口、移动、字体放大、键盘焦点、减少动态效果与透明度 | 同一组件的原生截图与操作记录；结构不明时补窄屏稿 | 遵守 SPEC 断点与宿主 token；回退后层级与全部操作保留 |
| X04／P0 | CSS 磨砂与 simple 局部折射候选、中文输入、滚动、资源释放 | 同内容/背景的原生对比与性能记录 | 文字与点击区域不变形；未过小样时保留 CSS 基线，不启用整窗捕获或 WebGL |

五张主图使用同一套组件设计与 fixture 定义。V03、V04 可以是同一任务的不同时间快照；V05 可选既有归档记录。图间的时间变化必须在场景注释里声明，而不是悄悄修改标题和编号。

## 3. 每个主图需要表达的最少信息

### V01：看板首页

- 复用宿主框架，Trackers 模式对应工作区的任务看板；左边明确显示“视图／类型”。允许折叠其他左侧分组，不能把侧栏新增内容塞成另一块中央面板。
- 默认显示可执行类型的四列；“All／全部类型”是可进入的原生视图，不表示所有类型都能自动运行。
- 保留显示模式、保存视图和过滤的轻量入口；一个全局搜索，不重复画两个同用途输入框。
- 五张初始卡片，右栏关闭时中央扩展。新建只出现在允许的位置。

### V02：待办和启动

- 默认选中“PDF 行间对译”。来源是任务出处，正文与依赖仍归原生 Tracker。
- 任务标题和正文可编辑；验收项、上下文、目标设备及 provider 展示于任务详情／启动摘要，不常驻中央。
- 显示保存与开始模拟的区分；完整启动表单、字段错误、断网和版本冲突通过 fixture 验证，不要求全部塞进一张图。

### V03：运行会话

- 在 v2 的密度和三栏结构上修正视觉合同 VC-01 至 VC-08；沿用品牌与主题语义，按新材质地图落实磨砂层次。
- 右侧设备名是当前 run 的只读元数据，不是可以更改正在执行设备的下拉框。
- 工具输出按需展开，保持稀疏中央。消息列表与输入草稿在切标签时保留。

### V04：差异和验收

- 选中任务仍在运行列的待审状态；右栏显示当前 run 的基线、文件差异与必需验收项，细节按需展开。
- “接受结果”在政策允许时才可用；“要求修改”进入明确的新执行路径，不能把普通聊天发送当重试。
- 验证失败、豁免、证据未到齐属于 X02 状态，不为了画面整齐伪造全绿。

### V05：历史和归档

- 选中归档列中“工作台布局初稿”，保持相同 Tracker 身份。明确显示归档、归档前结果和恢复入口。
- 右栏按 run 展开历史，当前查看哪次执行清楚；人工评论与 Agent 执行事件区分。
- 恢复返回原语义状态；查看旧 run 不改变当前执行、不新建会话。原生 Release 记录不放入该列做示例。

## 4. 交互优先于生图的项目

X01 使用同一 provider／atoms／命令入口完成双向修改；对照证据包含 `(projectId, trackerId)` 与 revision。成对截图应来自同一次真实演示操作，不能用两张生成图当成一致性测试。

X02 至少覆盖：requested 接收前仍待办、accepted 后运行、等待回答绑定请求、验证失败不可完成、取消未确认不可重试、失联待核对、409 保存冲突、归档恢复、只读来源限制、长标题、搜索无结果。拖拽、键盘等价操作、返回焦点与新消息不抢滚动都需实际操作。

X03 继承 SPEC 的 1586×992 主视口及 1280、1024、768、390 CSS px 检查点，并检查 200% 字体；按 ≥1536、1100–1535、768–1099、<768 的策略适配。深色从同一语义 token 切换。主视图图片的分辨率不是响应式功能证明。

X04 按视觉合同的材质地图与小样方法执行：默认先交付 CSS 磨砂；simple 局部折射在相同构建/设备/窗口下单独测量，再决定是否纳入默认界面。真实操作覆盖中文组合输入、文本选择、滚动、Tab/Escape、焦点恢复、浮层裁切和主题切换。运行中切换减少动态效果及关闭透明度，验证立即回退。每次捕获记录材质模式与未测项，不把静态效果图或库安装结果当作通过。

## 5. TUI 实现截图与操作基准

TUI 与 GUI 使用同一 demo 服务和 fixture 版本；以下场景必须由实际 TUI 运行捕获，不能生成仿终端图片。截图覆盖外观，PTY/ConPTY 记录覆盖输入与状态变化，两者都需要。

| 场景 | 与 GUI 的关联 | TUI 交付与判定 |
|---|---|---|
| TV01 首页与选择 | V01 | 实际列表/看板截图；键盘和鼠标选择、筛选、类型与保存视图入口可达，窄终端切阶段列表 |
| TV02 编辑与启动 | V02 | 实测新建、正文/字段/依赖编辑、保存和模拟启动；中文输入/粘贴正常，保存不隐式执行 |
| TV03 会话与请求回答 | V03、X02 | 当前 run 会话、等待输入、补充输入和取消可操作；回答绑定请求，断连/重连保留关联与草稿 |
| TV04 差异与验收 | V04、X02 | 查看基线/差异/证据并执行接受或要求修改；缺证据、冲突或必需 Hook 拒绝时动作明确受阻 |
| TV05 历史与恢复 | V05 | 查看只读旧 run、归档及恢复；恢复不重跑，关闭 TUI 不取消执行 |

按视觉合同检查 120×40、80×24、160×48 字符网格，并在同一 PTY 会话 resize 往返。实测完整键盘路径、鼠标选择/滚动/菜单、焦点返回、中文宽字符与输入法、长标题、低色彩状态、退出后的终端模式恢复。GUI 的 CSS 尺寸与 200% 缩放检查不替代这些终端检查；输入法/真实终端鼠标能力需补实际终端操作证据。

跨端执行 GUI 创建 → TUI 编辑 → CLI 查询，再由不同入口模拟执行、验收、归档、恢复；核对同一 `(projectId, trackerId)`、revision 与 run 关联。纯无图形环境还须独立完成终端闭环。注入必需 Hook 拒绝/超时、提交后投递失败、重复及重连场景，用关联事件和查询断言核实结果；三端不得绕过守卫。分别报告补充规格的 PAR-01/02、HEADLESS-01、CLI-01、TUI-01、HOOK-01/02、EVIDENCE-01、LIFE-01，既有 UI/FLOW/MAP/REG 继续有效。

## 6. 产物命名与生成纪律

后续可采用 `V01-board-overview-candidate` 等场景名；本轮只定义逻辑名，文件未生成。每份产物旁记录：场景、fixture 版本、主题、视口、选择的 tracker／run、所依据的规格版本、生成工具或实现提交。

TUI 使用 `TV01-overview-implementation-capture` 等逻辑名，另附操作脚本/PTY 记录、字符网格、终端/系统版本、字体及输入能力、实际命令结果、事件关联与查询断言。合成 demo、真实后端及未验证项分开记录，不把示例文件名写成已存在的结果链接。

没有文件就不要创建“已完成”链接。不得在每张图里独立发明数字、任务数据、在线设备、验收结果或完成策略。先修正母版，再复用同一参考图生成后续状态；完成后核对文字、入口、数量、类型与按钮语义。

## 7. 何时能成为基准

1. 候选符合 Trackers 映射与视觉合同，未保留 v2 的八项冲突。
2. 用户已经审阅需要确认的主布局／关键动作，并明确接受该版本；未得到反馈不写“最终批准”。
3. 把接受范围与未决定事项记录下来。截图只批准视觉方向时，不外推为全部状态机或信息模型批准。
4. GUI 用原生组件、TUI 用实际终端实现捕获同 fixture 的截图，执行 GUI 双面板、三端业务对等及终端输入验收；原型、模拟、真实 Worker 分别标记。

M0 的交付包含可启动、可操作的 Nimbalyst GUI、独立 TUI、结构化 CLI、共享隔离 demo 服务和合成 Hooks 测试，以及 GUI/TUI 实际截图、PTY 记录与查询断言报告。五张 GUI 候选图继续用于视觉设计；AI 生成的终端图、CLI 冒烟或 Hook 成功日志不能替代 TUI 验收。
