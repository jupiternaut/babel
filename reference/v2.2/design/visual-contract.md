# Nimbalyst 执行看板：视觉合同

版本：候选 v1，2026-09-14。状态：待实施的视觉基准约束；不是用户已批准的最终效果，也不是运行时验收记录。

依据：[开发 SPEC](../NIMBALYST-DEVELOPMENT-SPEC.md)、[Trackers 一一映射](../NIMBALYST-TRACKER-MAPPING.md)。现有 [v2 图](babel-dashboard-v2.png) 与 [生成提示词](babel-dashboard-v2-prompt.md) 用于方向参考；本合同修正它未表达的新映射要求。计划见 [视觉覆盖矩阵](UI-VISUAL-PLAN.md)，后续生成用 [逐图提示词](UI-IMAGE-PROMPTS.md)。

## 1. 必须保持的产品结构

- 原生 Trackers 与执行看板是同一记录的两种布局：`card.id = TrackerRecord.id`，业务唯一身份是 `(projectId, trackerId)`。设备、服务和运行统计不是 Tracker 类型。
- 原生的类型、保存视图、生命周期筛选是三个维度。Ready 不等于所有 TODO；Releases 不等于归档；approved 不等于 done；closed 不等于成功。
- 左侧保留可折叠 Trackers 分组，内部有“视图／类型”，动态承接原生及自定义入口；设备、项目、集成、运维与它并列。只展开当前需要的层级，提供明确滚动区域。
- 默认执行视图中央只显示轻量工具栏、四列及卡片。默认四列“待办／运行／完成／归档”；不加入设备指标卡、同步大横幅或日志面板。切换原生 Trackers 显示模式时保留其原布局，四列规则不覆盖原生表格或类型视图。
- 单击卡片只选择并打开右栏；不启动执行。布局变化和标签切换不卸载正在工作的会话或编辑器。
- TODO 右栏承接原生说明、字段、依赖及验收；已执行任务右栏提供会话／差异／历史。任务讨论与 Agent 补充指令分别处理。

## 2. 修正 v2 的八项清单

| 编号 | v2 的不足 | 实施及后续图稿要求 |
|---|---|---|
| VC-01 | 省略原生视图／类型树 | 左侧补 Trackers，可折叠保留 Ready、全部、七种原生类型及自定义类型；不挤到中央 |
| VC-02 | 运行、完成、归档列头画了加号 | 新建只保留在待办列和全局入口；其他列只有必要菜单 |
| VC-03 | 左栏与顶栏都有搜索 | 优先复用宿主全局搜索；如确有导航筛选需求，必须使用不同标签与明确作用域 |
| VC-04 | 新建按钮统一叫新任务 | 执行总览新建 Task；进入 Releases 等原类型视图时，复用“新发布／新建当前类型”语义 |
| VC-05 | 未表示原生显示模式和保存视图入口 | 使用轻量显示／筛选菜单保留原生模式与保存行为；不复制第二组大工具栏 |
| VC-06 | 卡片无法解释混合类型 | 默认筛可执行类型；混合时用简小类型图标或筛选上下文区分，保留 Bug／Plan 身份 |
| VC-07 | 右侧只有运行聊天 | 补 TODO 原生详情、按 run 的差异／历史及单独讨论入口；普通条目聊天不冒充当前 Pi 会话 |
| VC-08 | 在线和同步示例像真实数据 | 无 Key 原型统一显示“演示数据”；设备数字按非终止 run 计，不和含异常卡片的运行列数混用 |

原截图中的 Releases 空列表只说明当时选中了发布类型，不能据此认定 Nimbalyst 没有看板或归档功能。

## 3. Token 与尺寸来源

实施时首先定位宿主现有 `--nim-*` 变量及共享组件，记录真实变量到语义角色的对应；未核验前不编造上游变量名。需要的角色为画布、侧栏、浮层、分隔线、主文字、次文字、选择态、焦点、成功、警告、错误。已有变量优先；确需新增时说明未能复用的原因，并同时提供浅色／深色值。

以下数值沿用开发 SPEC 第 3.3、3.5 节，不是额外创建的新设计系统：

| 项目 | 基准 |
|---|---|
| 主验收视口 | 1586 × 992 CSS px；现有图实际为 1586 × 992 像素，不宣称 4K |
| 三栏参考宽度 | 左侧约 240、右侧约 390、中央约 956 CSS px；允许宿主边框与拖宽适配 |
| 中央列宽 | 四列最小 220 CSS px；宽屏充分可见，窄屏使用规定降级 |
| 卡片 | 常规高度 64–88 CSS px；长标题／字体放大允许自然增高 |
| 间距 | 4／8 px 体系 |
| 正文／辅助字 | 14／12 px；遵循宿主字体与中文回退 |
| 分隔／圆角 | 1 px 分隔，4–8 px 圆角 |
| 触屏主要操作 | 至少 44 × 44 CSS px |

“约”表示布局参考，不应在图像生成结果上假定精确像素。代码布局及浏览器／宿主实际截图才用于尺寸验收。不要为了模仿图片缩小系统字体、压缩点击热区或硬编码卡片高度。

| 可用宽度 | 继承的布局策略 |
|---|---|
| ≥1536 | 三栏并列；左右可拖宽；优先保证四列可见 |
| 1100–1535 | 侧栏可折成图标；详情覆盖或并列；必要时显示横向滚动条 |
| 768–1099 | 侧栏抽屉；右侧覆盖；中央可横向滚动 |
| <768 | 单阶段列表＋阶段切换；详情全屏 |

1800+ 宽度增加留白，不增加监控面板。浅色为主要设计方向，深色使用宿主主题；禁用共享组件硬编码黑白背景、玻璃／发光／森林壁纸、大幅渐变和装饰性统计卡。

## 4. 组件与交互合同

### 卡片

标题最多两行，辅助信息最多一行，右上角有键盘可达的省略菜单。选中只改变细边框，不改变尺寸。默认不显示设备名、指标、完整仓库路径、长日志、头像堆叠或缩略图。异常使用“等待输入／失败／失联”等文字，不能只靠颜色。

悬停主动作不能挤动布局；菜单和右栏保留等价入口。待办拖入运行必须走启动命令；拖入完成必须满足验收守卫。视觉上不能提供任意改成功状态的暗门。

### 右栏

- TODO：原生标题、字段、正文、依赖／上下文、验收要求；启动表单清楚区分保存和执行。
- 运行：当前 run 的会话、工具活动和补充输入；等待输入时显示绑定请求的明确回答入口。
- 审查：差异绑定 run 与基线，验收项区分 passed、failed、skipped、人工豁免；可接受时才提供生效的接受动作。
- 历史：分别表示任务活动／讨论与执行记录。切旧 run 只读查看，不改变当前 run。
- 归档：保留归档前状态、结果和历史；恢复不自动启动。终止后普通输入只保存备注，重新执行须显式动作。

关闭详情后焦点回到所选卡片；读旧消息时新消息不抢滚动；切标签、卡片和调宽度保留相应草稿与编辑器状态。

## 5. 一份演示数据供所有图与交互使用

所有场景使用开发包统一的 [demo-fixtures.json](demo-fixtures.json)，本文件不另建数据副本；不得每张图自行创建任务、改 ID 或随机计数。该文件是设计场景描述，需经 NB-01 适配为原生 Schema；不是可直接向生产接口提交的记录。

主画面沿用五条初始任务：PDF 行间对译、整理研究资料、接入任务同步、统一任务状态、工作台布局初稿。主画面初始分布为待办 2、运行 1、完成 1、归档 1。后续状态图必须注明是哪个情景快照，数量随该快照计算，不能保留不相符的列头。

数据必须保存稳定 projectId、trackerId、类型、原生状态、revision、runId、执行次数与来源；五条主记录外的 Bug、Release、approved、cancelled、文件只读等语义测试记录只在相应场景筛选中显示，不要求全塞入首页。

固定演示时间，禁止每次截图随机更新相对时间。记录逻辑视图、fixture 版本、主题、视口、选中条目及 run；数据与文案必须与规格一致。图片生成无法保证文字和计数准确，必要时回到实现截图，不通过改规格迁就错误图片。

## 6. 基准的状态和证据

现有 v2 标为 `direction-reference`。后续图先标 `candidate`，完成映射核对和用户审阅后才记录 `accepted-baseline`；不要自行宣称用户已批准全部状态。

真实实现截图另标 `implementation-capture`，附构建提交、运行模式、视口、fixture 版本和检查结果。构建成功、漂亮图稿、模拟数据和真实 Pi 执行是不同证据。视觉基准不证明两面板读写一致、状态机正确或已接入设备。
