# ADR-002：桌面式入口与统一任务/Agent 看板

> 主底座选择已由 [ADR-003](ADR-003.md) 取代：确定 Nimbalyst，增加完成/归档、Google Tasks 与 SSH 后台。本文作为历史决策保留。

日期：2026-09-14。

状态：用户方向已记录；具体基础仓库仍待原型验证。

## 背景

用户明确：TODO 与 Agent 看板在一起；启动 TODO 创建 Pi 执行，任务结束后进入 ACHIEVE。通讯软件承载讨论，不承担整个运行界面。随后要求采用提供的 Ubuntu 桌面视觉作为入口，并参考 Hermes、Cline 开源看板。

## 决策

1. 用响应式 Web 工作台提供桌面式统一入口；Ubuntu 为服务宿主候选，各设备访问相同应用。
2. 一个 task_id 贯穿 TODO、RUNNING、ACHIEVE；一次执行一个 run_id，重试保留历史。完成与归档分离，异常不能算成功。
3. Babel 服务拥有任务正文、状态和执行关联；聊天是来源及交互入口，GitLab 是交付系统。
4. 工程候选：Cline Kanban 的界面/执行工作台，Hermes 的持久任务、调度和事件模式。是否直接 fork 尚未确定，Pi 接入仍需开发。
5. 入口不限定 Nimbalyst 为唯一宿主；继续保留其文档/会话与 AFFiNE 知识能力的复用价值。

详细设计、固定提交、源码导航和验证链路见 [入口与看板增补](../ENTRY-AND-BOARD.md)。

## 对 ADR-001 的影响

取代 [ADR-001](ADR-001.md) 中“Deck 拥有任务正文、Nimbalyst 是固定开发主前台”的默认安排。Nextcloud 身份与文件依赖需要重新选型，不自动换成另一个未验证产品。

保留文件访问约束、执行隔离、幂等、失联/取消确认和 PDF/Ops 验收要求。旧 SPEC、OpenAPI 和任务清单是历史基线，必须一致迁移后才能进入新架构实施；结构校验通过不代表这一迁移已完成。

## 后果

可先围绕单一任务服务实现最小闭环；无需部署多套任务数据库再相互同步。代价是需要核实 Cline 的终端、权限及跨设备边界，并实现 Pi 事件适配、共享身份和移动布局。实际部署、选定 fork 及多设备通过情况都不能由本记录推定。
