# ADR-001：保留前端与领域数据，统一项目和执行协议

状态：Proposed for implementation（作为本规范默认；不代表用户已批准部署）。日期：2026-09-13。

## 背景

用户希望六平台共享文件/聊天，聊天派发Pi任务，监控Ubuntu并阅读双语PDF；同时尽量保留Nimbalyst与AFFiNE交互。各产品已有数据协议和许可边界，直接统一数据库会损失离线、协作和升级路径。

## 决策

1. Nimbalyst为开发前台，AFFiNE为知识前台；共享project/task/run/resource ID，保留原文档协议。
2. Deck为共享任务正文权威。V1只导入/读取/跳转原生编辑；Gateway只拥有spec快照与执行数据，避免无CAS的Deck全量PUT覆盖。
3. Nextcloud LoginFlowV2委托用户身份，Gateway独立session绑定；不用admin代理所有用户。AFFiNE原账号/权限不自动合并。
4. PostgreSQL承载事务队列/outbox/幂等/lease。首版单服务，无额外消息集群。
5. Nextcloud SFTP external只读；managed独占新目录允许受控小文本写。更广泛编辑以后实现，不谎称SFTP提供强CAS。
6. Pi Worker全进程隔离，发布凭据留Gateway代理；失联不自动重派，取消需停止确认。
7. PDF与Ops分阶段接入同一权限及资源模型，保留明确现成/二开边界。

## 比较过的方案

- Nextcloud唯一UI：统一入口较快，但不符合保留现有前台偏好。
- 所有软件接一个数据库：UI可能少动，协议/迁移成本高且破坏本地协作语义。
- Nimbalyst商业同步服务直接自托管：不能由客户端MIT推导该权限，未作为依赖。
- 同时采用Nextcloud和SFTPGo：重复文件权限和索引维护；首版只选前者。
- Deck与GitLab Issues双向可写：引入任务正文冲突，无当前必要性。

## 后果

需要开发适配器和移动响应式页面；不会凭安装服务器获得一个全功能原生手机App。现有用户目录首版不能远程直接保存，必须清楚显示只读。保留升级路径与可追溯原任务，优先跑通单Worker闭环。

如果更换任务权威或文件网关，新增ADR并明确迁移及回滚；不编辑旧历史记录来隐藏变化。
