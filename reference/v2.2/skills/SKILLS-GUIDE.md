# 开发包内的设计技能

这三份技能用于已有 Nimbalyst 界面的局部设计与检查。它们是从本机保存的 Interfaces 上游源码快照携带的参考文件，不是已经接入 Nimbalyst 的插件，也不会自动安装或执行。项目功能、Tracker 映射和用户已经确认的视觉方向决定实现；技能只补充专项判断。

## 按工作选择，不同时加载整套

| 当前工作 | 读取入口 | 作用 |
| --- | --- | --- |
| 左侧导航分组、中央卡片布局、右侧详情展开、尺寸适配 | [better-layout](vendor/better-layout/SKILL.md) | 用既有组件与 tokens 保持阅读顺序、间距和渐进展开 |
| 卡片、菜单、弹窗、输入框与拖拽交互 | [better-accessibility](vendor/better-accessibility/SKILL.md) | 焦点、键盘替代操作、语义、可访问名称与状态提示 |
| 状态标签、按钮、失败提示与空状态 | [better-writing](vendor/better-writing/SKILL.md) | 让文字对应实际动作和结果，避免任务与执行状态混淆 |

需要相应专项时，由开发 Agent 显式读取入口，再按需读取入口链接的参考文件。不把 `skills/vendor/` 全量粘贴进提示词，不修改用户全局技能目录，不额外注册项目 hook。若某个 Agent 工具支持自动技能发现，接入应是后续明确的配置工作；本包目前只提供可移植的参考文件。

## 本项目适配规则

1. **保留已有产品系统。** 使用 Nimbalyst 既有组件、字体、图标库、主题与 tokens。以开发规格、Tracker 映射及已确认的第二版布局为准，不能因为技能给出通用默认值就重建整个 UI 或组件库。技能里的数值只在对应规则适用且与项目明确约束兼容时使用。
2. **中央保持简洁。** 左侧容纳工作区、设备、项目、视图和集成入口；中央显示任务生命周期列及少量必要卡片信息；选中任务后在右侧展开正文、会话、差异与执行历史。不在中央加入设备状态大卡、装饰图表、营销首页、轮播或无必要动效。
3. **同记录、同 ID、同数据源。** 原生 Trackers 与新看板是同一条记录的两个视图，不为看板复制一套任务。类型、Saved Views、Ready、正文和会话关联按 `NIMBALYST-TRACKER-MAPPING.md` 映射；技能不能改变领域契约。
4. **状态文案忠实。** Releases 是发布记录，不是归档；`approved` 不等于完成；创建 Session 或草稿不等于 Agent 已开始执行。启动、失败、完成和归档标签必须对应规格规定的事件与实际可验证状态。尚未取得有效观测显示“未知”；超过 freshness 阈值显示“快照过期”；最近连接探测失败按实际层级显示“SSH 不可达”或“节点不可用”，并展示观测时间。未知或过期不能推断设备离线、Agent 已停止；SSH 可达也不等于 Worker 或 Agent 可用。
5. **先完成无 Key 原型。** 原型只读固定或明确隔离的模拟 fixtures，清楚标记演示数据。交互可以演示创建、选中、筛选、移动与展开，但不能调用云端 Agent、读取已有凭据、SSH 连接真实设备或把模拟状态写入实际项目。真实运行接入属于后续阶段。
6. **卡片不只支持鼠标。** 选择、打开详情、启动菜单等有键盘路径；拖拽提供等效菜单或按钮操作；弹窗关闭后恢复焦点。在线、等待、运行、失败与完成不能仅靠颜色区分。细节区更新不会抢走输入焦点。
7. **按实际支持尺寸验收。** 宽看板可在自身容器横向滚动；窄屏提供合理的列表或分段视图，不强迫四列挤入 320px。检查 200% 缩放、中文长标题、空数据与错误状态；技能的通用回流建议不替代项目明确的尺寸和布局规格。
8. **核对真实组件。** 视觉与交互检查使用实现中的组件和实际主题。截图与效果图只能说明外观，不能证明键盘、数据写入、任务状态与 Agent 运行已经验收。
9. **如实报告。** `Block` / `Approve` 是技能给出的审查结论，不是新增用户许可流程。未运行的检查写“未验证”；发现问题则按已授权的工作范围修复并复测，不能用技能格式掩盖遗漏。

## 为什么不把所有设计技能都放进来

本机此前保存的 7 套、166 个设计技能是技能库，不是这次项目的必需依赖。对现有 Nimbalyst 做可追溯的局部改造，三份专项指南更容易保持一致。

| 未默认携带 | 原因 |
| --- | --- |
| Impeccable | 本机版本的入口要求运行原生 CLI，首次可下载二进制，带有路径及运行环境依赖；也可能引入另一套设计文档与 hooks |
| better-ui | 包含强制按钮缩放、图标模糊与动画数值，本阶段优先沿用现有 Nimbalyst tokens 与动效 |
| break | 擅长单组件样本检查，但“只看一次”和无现成浏览器则跳过等流程限制不适合作为本项目总验收流程 |
| Taste、Scroll 与营销视觉类集合 | 主要面向创意页面、首屏或滚动展示，容易扩张中央看板；部分依赖外部素材生成服务 |

后续如果确有专项设计问题，增加一份与问题匹配的技能即可，不需要为了“给 Agent 更多上下文”而全量复制。
