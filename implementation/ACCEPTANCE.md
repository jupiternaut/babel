# Windows 原生 M0 复验 · 2026-09-16

这是一份有边界的验收记录。原生 Nimbalyst 任务闭环已取得实际窗口与 ConPTY 证据；**完整巴别塔产品和全仓库发布门禁仍未通过**，本分支按候选实现提交，不合并为正式完成版本。

## 源码与形态

源码在 [nimbalyst](nimbalyst/)，上游公开 MIT 基线 `d6e1d008d9ee264a7447f3533fa9f48f158a70b0`。包含接手时已有实现和本轮修复；未来模块的存在不代表已验收。

保留原生 Trackers 及类型树、保存视图、卡片、详情和 Agent 工作区。Babel 是 Trackers 内的执行视图，不是替换整个原生菜单的独立网页。默认折叠连接诊断，侧栏统一滚动，避免说明文字挤压原生导航。

## 本轮修复

1. 演示工作区改为精确路径匹配，拒绝旧路径和名称相似的目录；POSIX 路径保持大小写。Vite 显式传递非敏感路由配置，使独立 profile 真正生效。
2. 关闭领域服务后，迟到的 Hook 结果不再写入已处置的存储；待投递记录保留。修正重试测试的等待条件。
3. TUI 搜索提交后立即清除旧选中记录和 runId，避免快速按开始时启动旧任务。
4. 原生右侧详情订阅共享数据源事件，CLI/TUI 执行后刷新 run、阶段和验收能力。
5. 修正宿主新建字段、测试桩和新增包的类型错误；补齐构建依赖后通过全工作区类型检查。

前四项均观察到回归测试从失败转为通过，不是仅凭代码判断。

全仓库失败横跨原有 Electron、runtime、node、CLI、marketplace 和 extensions。该次失败清单没有 Babel 测试；但尚未在干净上游工作树逐一做对照，因此不把全部失败归因于上游或 Windows。[失败摘录](evidence/full-gate-failures.txt)。全仓库检查后，本轮新增修复另经定向测试与真实窗口验证，未重复跑整套大测试掩盖旧失败。

实际交互覆盖：

- GUI 创建中文标题，CLI 读回同一 ID。
- ConPTY 中搜索任务、发起模拟执行；CLI 与 GUI 历史确认相同 runId。
- GUI 验收完成，CLI 查询 DONE，TUI 显示完成；切原生视图仍可找到同一条记录。
- CLI 启动另一任务，确认尚在运行时关闭 GUI；独立服务继续到待验收，TUI 完成验收，CLI 再确认 DONE。
- 另行实际执行 CLI `review accept` 并读回 DONE。
- 右键仅打开菜单、不改 revision；恢复和归档往返后 runId 保持不变。
- 宽窗口显示四列、窄窗口显示阶段列表；ConPTY 输入中文并 resize。真实鼠标点击终端及断线重连仍需补验。

身份记录见 [identity.json](evidence/identity.json)。[最终原生窗口](evidence/native-final.png)、[窄窗口](evidence/native-narrow.png)。图片里新增的验收卡是本轮测试留下的隔离数据，不能再用固定 2/1/1/1 判断该 profile 的正确性。

## 未通过或未做

- 全仓库 206 项失败需独立归因与处理；不得跳过门禁合并为正式产品。
- OP-03 原生正文/字段编辑与跨端冲突的全部真实输入路径尚未完成；现有编辑测试主要是领域/适配验证。
- 真实终端鼠标、全部菜单、重连与退出后终端恢复尚未完整验收。
- 浅色截图由媒体偏好模拟生成，Electron 仍使用 dark 主题，**不计作浅色主题通过**。
- Pi 真进程、多设备 SSH、Google OAuth/同步、聊天服务器、运维修复和 PDF 阅读对译未接入。
- 服务重启时恢复 executing/verifying 的模拟任务仍有缺口；关 GUI 后继续执行不等于服务崩溃恢复。
- 多个原生扩展的 dist 尚未在本机完整构建；原生全部功能没有逐一回归。
- 本轮仅 Windows；macOS/Ubuntu、打包安装、系统玻璃材质均未验收。
