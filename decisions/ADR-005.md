# ADR-005：新增业务提供 GUI、TUI、CLI 等价入口和应用 Hooks

日期：2026-09-14。状态：按用户要求采用，待实现与验证。

## 决策

用户要求终端也能完成业务操作，模型能借助 Hooks 自动测试。因此更新 [主 SPEC](../NIMBALYST-DEVELOPMENT-SPEC.md) 与 [TUI/Hooks 契约](../NIMBALYST-TUI-HOOKS-SPEC.md)，M0 同时包含非图形共享核心、Nimbalyst GUI、可交互 TUI、结构化 CLI 和 Hooks。

业务能力先形成 command/query/event 合同，三端共用权威服务、权限、状态机和持久数据。GUI 工作区两种 Tracker 布局共用一个 provider；独立进程各有客户端适配，不强求共享内存对象。核心寿命不依赖窗口、终端或 SSH 连接。

校验 Hook 与提交后观察事件分开；Hook 动作不得绕过完成守卫。模型自动化结合命令、事件、查询和断言，另测 GUI/TUI 交互。至少一次事件投递需要去重、恢复与故障验证，不假定脚本恰好执行一次。

## 对既有方案的影响

保留 [ADR-004](ADR-004.md) 的 Nimbalyst、原生 Tracker 权威与三栏 GUI。扩展其单 GUI 原型范围，NB-00～04 先建立无头能力及三端/Hooks 闭环。生产 Gateway、Pi 和多设备仍分期，但各期新增能力继续进入 [功能对照表](../CAPABILITY-MATRIX.md)。

不把该决定解释为此刻已经重写全部上游编辑器。终端中的业务缺口必须显式记录；新增业务不得只在 GUI 实现后就标完成。PDF 图像等视觉差异不能被“输出文字”掩盖。

## 成本与验收

需要抽取现有图形环境耦合、增加终端适配、协议及交叉测试，M0 比单 GUI 原型范围更大。按 PAR/HEADLESS/CLI/TUI/HOOK/EVIDENCE/LIFE 加原有验收集合交付，不能仅靠构建或效果图验收。
